# ميعادنا ⚽

تطبيق لحجز ملاعب كرة القدم في مصر، بنوعين من المستخدمين: **لاعب** و**صاحب ملعب**.

> **المرحلة الحالية: واجهة فقط (UI/UX Prototype).**
> مفيش باك إند ولا Firebase ولا API حقيقي. كل البيانات تجريبية ومتخزنة في الذاكرة،
> وبتتمسح لما تقفل التطبيق.

---

## التشغيل

المتطلبات: Flutter **3.22** أو أحدث (Dart 3.4+)، و Android SDK، ومحاكي أندرويد أو موبايل متوصل.

```bash
cd ma3adna
flutter pub get
flutter run
```

- خط **Cairo** بيتحمّل من الإنترنت أول مرة (`google_fonts`)، فلازم المحاكي يكون عليه نت.
- تشغيل الاختبارات: `flutter test`
- فحص الكود: `flutter analyze`

## الدخول التجريبي

| الخطوة | القيمة |
|---|---|
| رقم الموبايل | أي رقم مصري صحيح (11 رقم يبدأ بـ 01)، مثلاً `01012345678` |
| كود التحقق (OTP) | **أي 4 أرقام** — مثلاً **`1234`** |

- **اللاعب** بيدخل دايماً على حساب «أحمد علي» عشان يلاقي حجوزات جاهزة.
- **صاحب الملعب** بيدخل على حساب «الحاج محمود عبد العزيز» وعنده ملعبين:
  «ملعب النجوم» (شغّال) و«ملعب الأبطال» (تحت المراجعة).

### جرّب المزامنة بين الطرفين

1. ادخل كلاعب ← احجز ميعاد فاضي النهارده في «ملعب النجوم».
2. اخرج وادخل كصاحب ملعب ← هتلاقي الطلب في «الطلبات» وفي شاشة «النهارده».
3. وافق على الطلب ← رقم موبايل اللاعب يظهر.
4. دوس على أي ميعاد فاضي ← اقفله أو سجّل حجز يدوي.
5. ارجع كلاعب ← الميعاد ده هيظهر «محجوز».

### ملاحظات معمارية

- **المواعيد المتاحة مش متخزنة**: بتتحسب في `SlotService` =
  مواعيد العمل − الحجوزات − المواعيد المقفولة. الكلاس ده pure، فممكن ينتقل للباك إند زي ما هو.
- **ربط باك إند حقيقي**: اكتب كلاسات بتطبّق الواجهات في `data/repositories/repositories.dart`،
  وبدّلها في `data/providers.dart`. الشاشات مش هتحتاج تتغير.
- بعد أي تعديل، `dataVersionProvider` بيزيد فكل الشاشات بتعمل تحديث. مع باك إند حقيقي
  ممكن تستبدله بـ streams أو realtime.
- `dayOfWeek`: الأحد = 0 … السبت = 6. لو وقت القفل أصغر من وقت الفتح
  يبقى الملعب بيقفل بعد نص الليل.
- رقم موبايل صاحب الملعب **مش بيظهر أبداً** للاعب، ورقم اللاعب بيظهر لصاحب الملعب
  **بعد تأكيد الحجز بس**.
- الحجز من التطبيق بيبدأ «مستني موافقة»، والحجز اليدوي بيبدأ «مؤكد».
- الإلغاء المجاني متاح لحد 6 ساعات قبل الميعاد.

## ربط الباك إند (APIs) — خطوات عملية

كل الشاشات بتتعامل مع **واجهات (interfaces)** بس، ومفيش شاشة بتعرف إن البيانات تجريبية.

1. اعمل كلاسات جديدة (مثلاً في `lib/data/api/`) بتطبّق الواجهات الموجودة في
   `lib/data/repositories/repositories.dart`:
   `AuthRepository` · `UserRepository` · `PitchRepository` · `BookingRepository`.
2. في `lib/data/providers.dart` بدّل `Mock*Repository(...)` بالكلاسات الجديدة — ده المكان الوحيد اللي هيتغير.
3. حساب المواعيد المتاحة في `lib/data/services/slot_service.dart` (كلاس pure) — انقله للسيرفر زي ما هو أو سيبه في التطبيق.
4. بعد أي تعديل (حجز، قفل ميعاد، موافقة) الشاشات بتنادي `ref.refreshData()` فكل البيانات بتتحدّث. مع باك إند فيه realtime ممكن تستبدله بـ streams.

### أماكن مهمة في الكود

| المكان | المحتوى |
|---|---|
| `lib/core/l10n/app_strings.dart` | كل النصوص (عربي فصحى) |
| `lib/core/theme/` | الألوان (فاتح/داكن)، الأيقونات، المسافات، الثيم |
| `lib/core/widgets/` | الودجتس المشتركة: أزرار، كروت، شارات الحالة، الهيدر الأخضر، البار السفلي، الحركات |
| `lib/core/utils/clock.dart` | ساعة بتتحدّث كل 30 ثانية للعدادات («بعد 10 دقائق») |
| `lib/features/*/…_providers.dart` | بيانات كل جزء (Riverpod) — الشاشات بتقرأ منها بس |
| `lib/features/owner/dashboard/widgets/` | أجزاء الرئيسية لصاحب الملعب (الهيدر، الإحصائيات، الإشغال، صف الحجز) |
| `lib/features/owner/pitch_form/steps/` | خطوات إضافة الملعب، كل خطوة في ملف |
| `lib/features/player/home/player_home_widgets.dart` | أجزاء رئيسية اللاعب (الهيدر، متاح اليوم، احجز مرة أخرى) |

### قواعد بسيطة للحفاظ على النظافة

- أي نص جديد → `S` في `app_strings.dart`، وأي لون → `AppColors`، وأي أيقونة → `AppIcons`.
- لو ودجت اتكررت في شاشتين → انقلها لـ `lib/core/widgets/`.
- الشاشة بتعرض بس؛ الحسابات والتحميل في الـ providers.
